# Testbed run results (seed = 42)

> **Status: authored document, not a generated artifact.**
> This file is the human-written interpretation of the runs. It deliberately lives at the
> repository root rather than in `results/`, because everything in `results/` is regenerated
> by `./reproduce.sh --clean` and would otherwise be destroyed by a clean rebuild.
> The numbers quoted below are asserted mechanically by `verify_results.py` (180 golden
> checks), so the text and the data cannot silently drift apart.
>
> **Claim-type discipline.** The interpretation below separates three kinds of statement,
> because mixing them is what makes a simulation result look stronger than it is:
> an **encoding claim** (a consequence of how we wrote a rule or a metric), a **mechanism
> claim** (a consequence of how the simulated agents interact), and a **target claim**
> (a statement about real cities or about the standards themselves). Only mechanism claims
> are empirical findings about the testbed. Encoding claims are properties we can usually
> derive in closed form, and target claims are hypotheses the testbed can falsify but not
> establish. This mirrors the manuscript's treatment and supersedes earlier wording in this
> file that presented encoding consequences as research findings.

- **Scenario suite** — scenario comparison: 6 sources x 200 timesteps = 1,200 handovers per scenario.
  Generated by `python3 run_all.py`.
- **Stress and sensitivity** — flood-event **stress contrast** + global sensitivity + figures.
  Generated by `python3 run_stress_sensitivity.py` (needs matplotlib for the figures). The experiment is
  called a stress contrast, not a calibration: the load and the stress profile are both
  assigned by the analyst in one table, so nothing is fitted to observed data.

Raw data lives in `results/`: `scenarios.csv`, `scenarios.json`, `sensitivity.csv`,
`sobol.csv`, `calibration.csv`, `calibration.json`; figures in `results/figures/`.

Three further files under `results/` are the supplementary tables named in the manuscript's
data-availability statement, and they are regenerated by the same run: `stress_contrast.csv`
(the injection/detection counts and Wilson intervals behind M3s), `sobol_samples.csv` (the
sensitivity design's inputs and outputs, from which `sobol.csv` can be recomputed) and
`estimator_validation.csv` (the analytic validation of the first-order estimators, both output
regimes). `results/SHA256SUMS` is the archive manifest. `README.md` §"Supplementary tables"
describes each one and the checks that guard it.

## 2. What the numbers say (insight first)

**① The diverging pair: high conformance with zero replayable evidence.**
Moving from B0 (no design) to S0 (full design): completeness M1 **0.000 → 0.981**, modelled
evidence-reconstruction cost M2 **5.823 → 0.118** (a ~49x reduction, in **arbitrary units** — M2
is a synthetic cost index, not wall-clock or person-day time), tamper resilience M5
**0.000 → 1.000**, conformance M6 **0.193 → 0.991**.

The informative case is the *partial* baseline B1, which has labels, encryption and audit logs
but **no signing/receipt**: it still scores **M1 = 0.000** while lifting M6 to **0.544**. B1
therefore passes **54.4%** of the weighted rule set while producing **no** handover a third party
can replay. That divergence — not the 0.000 itself — is the finding.

Its zero half is **definitional**, and we say so plainly: M1 requires a well-formed, signed,
untampered receipt, so a design without a receipt scores zero by construction rather than as a
discovery. The non-definitional content is that a design can look substantially compliant on an
aggregate rule count while being completely unauditable across a role boundary. The receipt is
**necessary but not sufficient**, and producing it is not free (manuscript §7.1).

**② The silent misclassification channel has a closed form — it is an encoding property.**
Under full design, M3s (misclassification detection) sits at **0.583** across all flood scenarios
— the plateau spans 0.5792–0.5833, a spread of only 0.004, i.e. it is insensitive to attack rate,
signature skipping, topology and scale alike. Raising the mislabel rate (S1, p_err 0.02→0.15)
pulls M3 down **0.892 → 0.794** and M6 down 0.991 → 0.978.

The plateau is not a discovery, and it can be derived. R1 checks that a class label is *present
and well formed*, never that it is *correct*; an injected mislabel is drawn uniformly among the
other classes; an upward mislabel is invisible to R2/R3 while a downward one is caught only
indirectly, when it triggers a downstream encryption/localisation failure. Detection therefore
collapses to

    M3s = 1 - (1/N) * sum_i s(c_i),     s(general) = 1,  s(important) = 1/2,  s(core) = 0

which depends only on R1's encoding and the profile's class mix. The flood profile (1 general /
3 important / 2 core) gives **0.5833**, which coincides exactly with the measured 14/24; the
transport profile (2/3/1) gives **0.4167** in closed form, whereas its measured ratio is 13/28 =
0.464, whose Wilson interval [0.295, 0.642] contains 0.4167 but does not resolve the predicted
0.167 gap at this sample size. These rates are ratios over a small number of injected
mislabels, so they are reported with Wilson 95% intervals — [0.388, 0.755]
for S0 and [0.295, 0.642] for S6 — rather than as point values.

Because the result follows from **our own encoding**, it is *not* evidence of a gap in
GB/T 43697-2024 or in any other standard, and an earlier version of this file read it that way.
The derivable statement is narrower and still useful: a rule that checks label *presence* cannot
certify label *correctness*, so a conformance regime built on such rules will report compliance
that a careless or malicious labeller can defeat silently. That is a **recommendation to
standard-writers**, not a measurement of their output.

**③ Topology and scale move latency only — by construction, as disclosed.**
Mesh vs star topology cuts M4 **1.249 → 0.850 (−32%)** with M6 bit-identical (0.9905 both ways);
scaling to N=12 stakeholders raises M4 **1.249 → 1.512 (+21%)** with M6 still bit-identical.

This invariance is **built in, not discovered**. Topology and stakeholder count enter the engine
in exactly one place — the latency term — and are never read by the rules or by any evidence path.
Reading it as an empirical robustness result would be circular. What the invariance does
establish is the intended **separability of the design**, which is what makes the framework
testable at all: the evidence dimension responds to control parameters and the performance
dimension to structural parameters, with no cross-talk between them.

Morris (μ* = 0 for n_stakeholders) and Sobol (ST = 0) agree, so they are consistency checks on
the engine's wiring rather than independent confirmation of a finding.

**④ Tamper resilience is non-degenerate only where the attestation exists.**
Under S4 (p_atk 0.01→0.08) M1 dips 0.981 → 0.910 and M2 climbs 0.118 → 0.331, but **M5 stays
1.000** — every tampered receipt is recovered because the signed attestation (EV2) lets the
receiver detect and re-derive it. Baselines B0/B1 score M5 = 0.000 precisely because they have
no signature to recover from, and S2 (signature-skip 0.10) lands at M5 = 0.929, in between.

M5 is defined over handovers that were **recovered or handed over**, and it is **undefined when
no attack occurred** — which is why the pre-event phase in §4 reports no value rather than 1.000.
Its non-degeneracy also depends throughout on our decision to model tampering as recoverable via
the attestation; a design in which a tampered receipt is unrecoverable would yield a different
metric, and the manuscript lists this among the threats to validity.

**⑤ Profile substitution shows interface portability, not cross-domain validity (RQ-E).**
Swapping only the profile to `transport` (S6) reproduces the flood trends: M1 **0.985 vs 0.981**,
M2 **0.108 vs 0.118**, M6 **0.991 vs 0.991**, and the adversarial variant behaves identically in
direction (M1 down, M2 up, M5 held).

The claim is deliberately narrower than "generality". What this demonstrates is that the engine
and R1–R8 can be driven by a different profile through a fixed interface without code changes —
**interface portability**. Similarity of the resulting numbers is largely guaranteed by
construction, because a profile can only carry a bounded set of facts (source classes, PII
designations, topology, stakeholder count, load) and nothing else varies.

The M3s difference (0.464 vs 0.583) is not a partial success or a near-miss: it is **predicted
by** the closed form in ② from the differing class mixes — a 0.167 gap in closed form that the
present sample cannot resolve — and it is the clearest illustration that these rates are encoding
properties rather than domain measurements.
Cross-domain validity in the sense of "these values would hold in a real transport twin" is not
tested here, and is listed as a limitation rather than a result.

## 4. Stress contrast against the SL/T 853-855 process

### 4.1 The event

SL/T 853-855-2025 defines the digital-twin water process as
**data baseplate → model → early warning → dispatch** (数据底板 → 模型 → 预警 → 调度).
The experiment encodes a **synthetic 36-hour urban flood event** as six phases, each
carrying an *evidence load* (relative handover rate) and a *control-stress* profile — under
time pressure operators misclassify more, skip signatures more often, and attackers get more
chances. The **stressed** run uses the per-phase stress; the **nominal** run keeps fair-weather
control quality (p_err 0.01, p_skip 0.005, p_atk 0.002) *at the same phase loads*. The
difference therefore isolates the effect of stress at fixed workload.

**Both the load and the stress profile are assigned by the analyst in the same table**, and the
stress profile moves three parameters together rather than one (p_err 0.010→0.080, p_skip
0.005→0.060, p_atk 0.002→0.030 across the event). This is a **scenario contrast under an assumed
coupling**, not a calibration to observed data, and the correlations reported in 4.2 inherit that
status. Calling it a calibration — as an earlier version of this file did — overstated it. The
SL/T 853-855 guidelines supply the *reading* of the phases, not the load or stress values.

The hydrograph is deliberately **in phase with the operational stages**, not with the raw
rainfall: rainfall peaks at 18 h (48 mm/h), the lagged catchment level peaks at **5.600 m at
22 h** — inside the dispatch phase — with the 4.5 m warning threshold exceeded 16–27 h and the
5.2 m dispatch threshold exceeded 19–25 h. The 2 h lead of the 4.5 m crossing over the declared
warning stage is intentional: a stage is *declared* once the level has held above the threshold.

### 4.2 Per-phase compliance

| phase | stage | load | M1 stressed | M1 nominal | ΔM1 | M2 str. | M2 nom. | M6 stressed | M6 nominal | ΔM6 |
|---|---|---|---|---|---|---|---|---|---|---|
| P0 pre-event | monitoring baseline | 1.0 | 0.983 | 0.983 | 0.000 | 0.092 | 0.092 | 0.994 | 0.994 | 0.000 |
| P1 data baseplate | 数据底板 | 1.6 | 0.974 | 0.990 | −0.016 | 0.157 | 0.100 | 0.982 | 0.991 | −0.009 |
| P2 model inference | 模型 | 2.2 | 0.977 | 0.981 | −0.004 | 0.124 | 0.099 | 0.991 | 0.993 | −0.002 |
| P3 **warning** | 预警 | 3.0 | **0.931** | 0.997 | **−0.067** | 0.247 | 0.083 | 0.974 | 0.994 | −0.020 |
| P4 **dispatch** | 调度 | 3.2 | **0.891** | 0.992 | **−0.102** | **0.340** | 0.096 | **0.963** | 0.991 | **−0.028** |
| P5 recession | 复盘 | 1.2 | 0.958 | 0.986 | −0.028 | 0.172 | 0.109 | 0.985 | 0.989 | −0.004 |

**Insight — under the assumed coupling, compliance is at its weakest exactly when it is most
needed.** Under stress, M1 completeness falls from the pre-event baseline into the event,
**0.983 → 0.931 (warning) → 0.891 (dispatch), a −9.3 pp fall**, and recovers only after the event
(0.958). The nominal control does the opposite: it *rises* slightly to 0.992–0.997 during
warning/dispatch because a higher handover count dilutes the fixed-rate error. The stress gap ΔM1
therefore widens from 0.000 at pre-event to **−0.102 at dispatch** — the loss is not a level
offset but an **interaction between operational load and attestation quality**, concentrated in a
9-hour window (18–27 h) that is precisely the window in which evidence quality matters most for
accountability.

This is the pattern the framework is designed to expose, and it is a **falsifiable hypothesis,
not a measurement of any real flood response**. Because the load and the stress profile are
assigned together by the analyst (4.1), the contrast cannot confirm that real attestation quality
degrades this way; it shows what the compliance posture would do *if* it does. Replacing the
assumed coupling with field data is the single highest-value next step.

The cost channel moves with the quality channel: modelled reconstruction cost M2 at dispatch is
**0.340 vs 0.096 nominal (3.6×)**, in arbitrary units. Across the six phases,
corr(load, conformance loss) = **+0.810** and corr(load, reconstruction cost) = **+0.835**. Since
both variables were assigned by the analyst in one six-row table, these coefficients are a
**coherence check on that assignment** — confirming that the highest-load phase also carries the
highest modelled stress — and **not** a regularity discovered in data. Six points is also six
points: no confidence interval is given because none would be meaningful at this n.

On the sub-metrics, one claim is **withdrawn**. We previously reported that M3s "collapses under
load" (0.667 → 0.429/0.500 → 0.690). Re-examining the per-phase counts, the per-phase mislabel
samples are tiny — 3 to 42 injected mislabels — and every stressed phase's Wilson 95% interval
**contains the closed-form value 0.5833** from §2②. The apparent collapse was sampling noise at
n = 3–8 in the early phases, and this file should not have read it as load sensitivity.

M5 tamper resilience is **1.000 in every stressed phase in which an attack occurred (P1–P5)**;
it is **undefined at P0**, where no attack occurs, and that is reported as no value rather than
1.000. Within that domain the signature channel does *not* degrade under event stress, so the
erosion is confined to the **human-attestation** channel (classification, localisation, signing
discipline) and never the cryptographic one. Had this held, the engineering reading would be
that hardening the certificate chain buys nothing during a flood and that *automated*
classification/localisation is what removes the operator as a single point of failure. We report
the sub-metric separation as observed, but the load-coupled part of it remains a hypothesis.

## 5. Global sensitivity (Morris screening + Sobol decomposition)

### 5.1 Estimator

Two independent estimators are reported because the classic Saltelli first-order estimator is
**not usable at this output variance**. M6 has a standard deviation of order 1e-2, so the
product term in the Saltelli S1 estimator is dominated by noise: at N = 128/512/1024 on
analytic test functions it returned S1 > 1 and negative indices (Σ S1 ranging −1.07 to 3.45).
Replacing it with a **binned conditional-mean estimator**
(S1_i approx. Var_bins(E[Y | X_i in bin]) / Var(Y), 10 equiprobable bins, N = 4000) and validating on
functions with known indices:

| test function | true S1 | estimated S1 |
|---|---|---|
| f = x0 + 2 x1 (additive) | 0.200 / 0.800 | 0.199 / 0.792 |
| f = x0 (single factor) | 1.000 / 0.000 | 0.990 / 0.002 |

These two rows are panel A of `results/estimator_validation.csv` at its recorded seed. An earlier
version of this file also quoted results for `x0·x1` and `x0 + 9x1`; those rows had no source in
the artifact — no script computed them and no check asserted them — so they could not be
reproduced and are not repeated here. Ten bins is a reported parameter, not an implementation
detail: the binned estimator is not bin-count invariant, and 10 is chosen because
`n_stakeholders` takes exactly ten integer values in its range (3–12), so every bin holds one
distinct level and that factor's conditional mean is a group mean rather than an average across
mixed levels.

Total-order ST is kept as Saltelli/Jansen (stable on the same tests). Both targets use 30
timesteps per model evaluation, giving 180 handovers per evaluation — roughly one sixth of the
1,200 used in the scenario runs — which is why the totals below exceed unity by about 8%.

The substitution was validated a **second** time at M6's own variance scale (output sd ≈ 0.012),
on analytic functions scaled to that magnitude. There the classic Saltelli S1 estimator fails
outright: it returns **1.155 / 0.972** for an additive function (true 0.5 / 0.5), **−0.039 /
0.917** for a pure interaction (true 0 / 0), and **1.927** for a single-factor function (true 1).
The binned estimator recovers **0.496 / 0.493**, **0.990**, and **0.427 / 0.422** respectively.

The third case is the important one: for a function whose true first-order effect is **zero**,
the binned estimator still attributes 0.427 and 0.422, so it is **biased upward under pure
interaction**. Reported S1 values are therefore **upper bounds** on first-order effects. This is
why Insight 2 below reads the interaction term cautiously, and why the negative ST − S1 entries
are treated as an estimator artefact rather than as evidence of negative interaction.

Σ S1 = 0.910 (M6) and 0.900 (M1); Σ ST = 1.078 (M6) and 1.083 (M1). The two negative entries in
the final column are **estimator artefacts, not negative interactions** — an earlier version of
this file rounded them to "~0" and so hid both the artefact and the ~8% excess in Σ ST caused by
the 180-handover evaluation budget. The `n_stakeholders` entries sit near zero because that factor
is evaluated at ten bins over exactly ten integer levels, so each bin is one level and the
residual is rounding rather than a spurious effect (see §5.1).

**Insight 1 — the two compliance objectives are governed by *different* controls.** For
**conformance M6**, adversarial pressure dominates (S1 = 0.400, i.e. ~40% of the variance) ahead
of skipping (0.259) and misclassification (0.249). For **completeness M1**, the ranking inverts:
**signature-skipping is the dominant factor (S1 = 0.530, > 50% of the variance)**, with attack
second (0.275) and misclassification a distant third (0.094). A designer optimising "conformance"
would harden against attack; a designer optimising "audit-ready evidence" must first fix *signing
discipline*. These are different engineering investments, and the testbed quantifies the split.

**Insight 2 — misclassification is the most interactive factor.** p_err has the largest
interaction term for both targets (0.107 on M6, 0.102 on M1, i.e. ~40–50% of its own ST), whereas
p_atk is almost purely first-order (ST − S1 ≈ 0.02–0.04). Substantively: an attack either breaks
the chain or does not — it acts locally; a misclassified datum propagates *through* downstream
encryption and localisation rules, so its damage depends on what else happens.

Two caveats travel with this reading. First, the binned S1 estimator is biased **upward** under
pure interaction (§5.1), so the S1 and ST − S1 columns are upper bounds and the interaction terms
are correspondingly generous. Second, p_err is the same factor whose detection rate is fixed in
closed form by R1 (§2②); the two statements are consistent — a channel that cannot be observed
directly is also one whose downstream consequences depend on the rest of the pipeline — but the
interaction term is **not** independent evidence for the closed form.

**Insight 3 — scale is confirmed a non-factor, as designed.** n_stakeholders has S1 ≈ 0.005 and
ST = 0.000 on both targets, corroborating the Morris μ* result (§3) and §2③: stakeholder count is
a **latency** lever only. Because the structural parameters never reach the rules or the evidence
paths, this is a check that the engine is wired as intended rather than a discovery about
compliance. The negative ST − S1 (−0.006 on M6, −0.005 on M1) is impermissible for a variance
share and is an artefact of the 180-handover evaluation budget, not a negative interaction.

**Insight 4 — Morris and Sobol agree on the dominant factor but disagree on the ordering of the
other two.** Morris μ* on M6 ranks p_atk ≈ p_skip > p_err (0.0229 ≈ 0.0226 > 0.0200), whereas
Sobol S1 on M6 ranks p_atk ≫ p_skip ≈ p_err (0.400 ≫ 0.259 ≈ 0.249). This is not a contradiction:
Morris μ* measures *mean elementary-effect magnitude* (a one-at-a-time, partly interaction-
inclusive measure) while S1 attributes *variance*. The divergence is itself the finding — p_skip
and p_err have comparable marginal leverage but p_atk concentrates more of the outcome variance.
Reporting both, rather than either alone, is what makes the attribution defensible.

## 6. Caveats (scenario suite and sensitivity)

- **No real data are used anywhere in this testbed.** Scenario data are **synthetic** (seeded at
  42); the flood event is a plausible generated hydrograph, not an observed record from a named
  city; no real facility, individual or institution is represented.
- External validity rests on the **SL/T 853-855 stress contrast** (§4) and on the R1–R8 standard
  anchors — and the contrast is a **falsifiable hypothesis, not a measurement**. Its load and
  stress values (p_err/p_skip/p_atk per phase) are assigned by the analyst in a single table, so
  the reported correlations check that assignment's coherence rather than discover a regularity.
  A field study is required to replace them with observed values.
- The **five roles run in a single process** sharing one seeded random stream. This is a
  single-process multi-role simulation, not a distributed deployment: there are no trust roots, no
  real message transport and no adversarial independence between roles. Cross-organisational
  behaviour is therefore modelled, not exercised.
- 20262810-T-907 is a **draft (plan number)**; used as a label only, and its clause numbering may
  change before publication.
- M2 is a modelled evidence-reconstruction cost **in arbitrary units**, not wall-clock or
  person-day time. M1 and M5 are partly definitional: M1 requires a signed well-formed receipt,
  and M5 is undefined when no attack occurs.
- Sobol S1 uses a binned conditional-mean estimator (validated in §5.1, where its upward bias
  under pure interaction is quantified); ST is Saltelli/Jansen. A zero ST for `n_stakeholders`
  reflects a factor with no effect **by construction**; a small negative ST − S1 is an artefact.
- All numbers above are asserted by `verify_results.py` (`make verify`, 180 checks, counted at
  run time). A change to a modelled parameter that shifts them will fail those checks by design,
  forcing this document to be reviewed rather than silently invalidated.
